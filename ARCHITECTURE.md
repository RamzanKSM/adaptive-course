# Архитектура Java-курса (MVP)

## Цель

Один веб-сервис для преподавателя и студентов: диагностика, уроки, задачи по Java, автоматическая проверка, помощь LLM и история работы. Источник продуктовых правил — `adaptive_java_tutor_mvp_spec_v4.md` и `java_initial_diagnostic_mvp_v2.md`.

## Состав

```text
Браузер (React)
    │ HTTPS / JSON
    ▼
Java-приложение (Spring Boot)
    ├── SQLite: пользователи, диагностика, уроки, прогресс, банк задач, чат
    ├── Codex App Server: объяснения, подсказки, генерация контента
    └── Piston API: компиляция и проверка Java-кода
```

Один backend-процесс владеет учебными правилами и доступом к внешним сервисам. Браузер не получает OpenAI API key и скрытые тесты. Piston доступен только backend. Redis, брокер сообщений, отдельные сервисы для учебной логики и PostgreSQL в MVP не нужны.

Первый преподаватель создаётся при чистом запуске из `APP_BOOTSTRAP_ADMIN_LOGIN` и `APP_BOOTSTRAP_ADMIN_PASSWORD`; готового общего пароля нет. Локальный Compose хранит SQLite и `CODEX_HOME` в отдельных томах, публикует веб-приложение только на loopback и не публикует Piston. Языковой пакет Java в Piston устанавливается отдельным шагом после первого запуска.

## Решение по LLM

В спецификации выбран Codex App Server и постоянный thread на студента и язык. Адаптер для `codex app-server` существует, но студентский LLM-чат отключён fail-closed: стабильный протокол App Server не предоставляет способ отключить command tools для недоверенного текста. До появления такой возможности или отдельно проверенной изоляции вопросы студентов не передаются в App Server. ID thread и история остаются частью планируемого безопасного пути.

Модель по умолчанию — `gpt-6-luna`, настраивается через env backend. Если безопасный runtime будет утверждён, `CODEX_HOME` находится в примонтированном каталоге, поэтому авторизация Codex переживает пересборку образа. Вход в другой ChatGPT/Codex-аккаунт оператор выполняет вручную через терминал того же контейнера и с тем же `CODEX_HOME`:

```sh
codex logout
codex login --device-auth
codex login status
```

Подтверждение device code нужно пройти под нужным ChatGPT-аккаунтом, затем перезапустить backend. Скрипта с rollback в репозитории нет. `codex login status` сообщает о наличии авторизации, но не удостоверяет личность аккаунта. Не следует выводить содержимое файлов с токенами или добавлять их в Git. Доступность старых thread под новым аккаунтом требует проверки; локальная история уроков в SQLite сохраняется. Для разделения сохранённых ID thread между аккаунтами используется не секретный namespace в конфигурации.

**Граница развёртывания:** официальная документация OpenAI указывает, что встроенная авторизация App Server не разрешена для hosted services. Поэтому текущая интеграция предназначена для локального MVP; доступ студентов к приложению на VPS с этой авторизацией не считается согласованным вариантом развёртывания. Перед таким запуском нужен разрешённый путь авторизации OpenAI.

Студенческие вызовы Codex по умолчанию выключены (`APP_LLM_STUDENT_RUNTIME_VALIDATED=false`). В адаптере задан изолированный рабочий каталог, ограниченное чтение, read-only sandbox и запрет сетевого доступа для команд модели. Перед включением требуется реальная проверка на целевом Linux-хосте, что попытка прочитать `CODEX_HOME/auth.json` или файлы за пределами разрешённого каталога отклоняется. До этой проверки backend не запускает Codex для чата студента.

Глобальный флаг LLM и флаг студента проверяются до **каждого** запроса к OpenAI. Повторное использование уже сохранённой задачи или объяснения не требует LLM.

## Данные и правила

- Диагностика использует 56 готовых вопросов. Пятый ответ «Не знаю» добавляет приложение. Ответы сохраняются, но не влияют на практический счётчик навыков.
- Студента создаёт преподаватель. Активный урок имеет явные начало и конец; диалог LLM живёт дольше урока.
- Задача хранит проверяемые навыки, необходимые предварительные навыки и скрытую Java-проверку. Новая задача и её проверка сохраняются вместе.
- Следующая задача сначала ищется в банке. Успешно решённая тем же студентом задача не приносит повторный зачёт. Прогресс меняется только после успешной проверки Piston.
- Итерация навыка — разные успешные задачи в одном уроке: в первой три (ступени сложности 1→2→3), во второй две (2→3), в третьей одна (3). Освоение — три итерации на уроках N, N+1 и N+3, всего шесть задач.
- Преподаватель видит сохранённые уроки, сообщения, отправленный код и результаты проверок. Скрытые тесты в ответах студенту отсутствуют.

## Порядок реализации

1. Запустить backend и frontend; настроить SQLite, вход по ролям и создание студентов.
2. Провести диагностику и сохранить результат.
3. Провести полный урок на подготовленных задачах: выдача, отправка Java-кода, Piston, прогресс, история для преподавателя.
4. Добавить объяснения и чат через OpenAI, затем генерацию задачи вместе с проверкой при отсутствии подходящей в банке.

Граница MVP — работающий полный сценарий, а не развитая аналитика или поддержка Python. Новые языки могут получить отдельные навыки, вопросы и прогресс позднее.
